# Provenance Guard

A Flask backend that a creative-writing platform can plug in to estimate whether a submitted text
was written by a person or generated by AI. It returns an honest confidence score, shows readers
a plain-language transparency label, lets creators appeal, rate-limits submissions, and keeps a
structured audit log of every decision.

> Design principle: **calling a human's work "AI" is worse than missing AI text.** Thresholds,
> labels and fallbacks all lean toward "uncertain" or "human" when the evidence is mixed.


The full pre-implementation spec is in [planning.md](planning.md). The architecture diagram is in
its `## Architecture` section.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
echo "GROQ_API_KEY=your_key_here" > .env      # .env is gitignored
python app.py                                  # serves http://localhost:5001
```

> **Port 5001, not 5000.** On macOS the AirPlay Receiver already answers on `localhost:5000`
> (curl returns `403 AirTunes`), so the app defaults to 5001. Set `PORT=5000` to override.
>
> **Model:** the assignment's suggested `meta-llama/llama-4-scout-17b-16e-instruct` now returns
> `404 model_not_found` on Groq, so the default is `qwen/qwen3.8-27b`. Set `GROQ_MODEL` in
> `.env` to change it.

|---|---|---|

## Architecture overview

A submission's path from input to label:

1. **`POST /submit`** receives `{text, creator_id}`. **Flask-Limiter** checks the per-IP limit
   (10/min, 100/day). The text is validated (20–20,000 characters).
2. The raw text goes to **three independent signals** (`signals.py`). Each returns a 0–1 score
   (0 = reads human, 1 = reads AI) plus details:
   - **LLM judge** (Groq) → `llm_score` + one-sentence reasoning
   - **Stylometrics** (pure Python) → `stylometric_score` + sentence-length CV, word length, informal markers
   - **AI-phrase markers** (pure Python) → `marker_score` + which phrases matched
3. **Confidence scorer** (`scoring.py`) weights the three scores into `ai_likelihood`. It
   shrinks toward 0.5 when the signals disagree, down-weights statistics on short texts, and
   requires corroboration before an AI verdict. Output: `attribution` (`likely_ai` / `uncertain`
   / `likely_human`) and `confidence`.
4. **Label generator** (`labels.py`) maps the attribution to one of three fixed plain-language
   labels.
5. **Storage** (`storage.py`, SQLite) inserts the `submissions` row and a `classified`
   **audit-log** entry with every score, then the JSON response is returned with a `content_id`.

**Appeal path:** `POST /appeal` → look up `content_id` (404 / 403 / 409 checks) → insert
`appeals` row → `submissions.status = under_review` and label swapped to "Under review" →
`appeal_filed` audit entry carrying the reasoning *and* the original scores → confirmation.

## Detection signals

Three distinct signals, chosen because each looks at a different property of the text: meaning,
structure, and vocabulary habits.

| Signal | What property it measures | Why it differs between human and AI text | What it misses |
|---|---|---|---|
| **1. LLM judge** (Groq, `temperature=0`, JSON output) | Holistic semantic/stylistic coherence: generic framing, balanced both-sides structure, lack of concrete lived detail | LLMs recognize the smooth, hedged register they produce themselves | It has no ground truth and can be confidently wrong. It is biased toward calling polished or formal writing AI: it scored a real academic sentence **0.95**. It can be swayed by what the text says about itself, and it gives coarse round-number scores. |
| **2. Stylometrics** (pure Python) | Structure: **burstiness** (coefficient of variation of sentence lengths), **mean word length**, **informality rate** (lowercase sentence starts, lone "i", `!`/`?`, ellipses, ALL-CAPS, slang) | AI text is uniform: even sentence lengths, consistently formal vocabulary, almost no casual punctuation. Human writing is bursty and messy. | It cannot read meaning. Formal or ESL writing looks AI-like, poems with equal-length lines break the burstiness math, and under ~40 words it's noise. |
| **3. AI-phrase markers** *(ensemble stretch)* | Vocabulary: density of ~50 stock LLM phrases ("it is important to note", "furthermore", "delve", "paradigm shift", "stakeholders"…) | Assistant-tuned models overuse a recognizable set of transitions and buzzwords | Trivially evaded by editing the phrases out. It punishes humans who naturally write "furthermore", and having no markers is only weak evidence of human writing. |

Stylometric sub-score mapping: burstiness CV ≤ 0.20 → 1.0, CV ≥ 0.65 → 0.0. Word length
≤ 4.2 chars → 0.0, ≥ 5.4 → 1.0. Formality = `1 − min(1, informal_rate × 12)`. Weighted
0.4 / 0.3 / 0.3.
Marker score = `1 − exp(−0.35 × hits per 100 words)`.

## Confidence scoring

**Combining (weighted ensemble with conflict rules):**

```
weights           = llm 0.50, stylometric 0.30, markers 0.20
short text (<40w) → stylometric and marker weights halved (statistics unreliable)
LLM unavailable   → dropped, remaining weights renormalized
ai_likelihood     = weighted average of available signals
if max − min signal score > 0.5  → ai_likelihood = 0.5 + (ai_likelihood − 0.5) × 0.6   (disagreement → pull toward "unsure")
confidence        = max(ai_likelihood, 1 − ai_likelihood)    (0.5 = coin flip, 1.0 = certain)
```

**Thresholds (asymmetric on purpose):**

| ai_likelihood | Extra condition | Result |
|---|---|---|
| ≥ 0.75 | LLM ≥ 0.6 **and** (stylometric ≥ 0.5 **or** markers ≥ 0.5) | `likely_ai` |
| ≤ 0.35 | — | `likely_human` |
| between, or ≥ 0.75 without corroboration (capped to 0.74) | — | `uncertain` |

The AI band is narrower than the human band, and the AI verdict needs a second signal to agree.
No single signal can get a text labeled AI. That's the false-positive asymmetry built into the
math.

**How I validated it.** I ran the assignment's four reference inputs plus a short repetitive poem
through `scripts/eval_inputs.py`, printing each signal separately:

```
input                        llm  stylo  mark  ai_lik  conf  attribution
------------------------------------------------------------------------
clear_ai                    0.98   0.84  1.00   0.942  0.94  likely_ai
clear_human                 0.05   0.05  0.00   0.041  0.96  likely_human
borderline_formal_human     0.95   0.95  0.00   0.656  0.66  uncertain  (signals disagree)
borderline_edited_ai        0.85   0.78  0.00   0.634  0.63  uncertain  (signals disagree)
short_repetitive_poem       0.15   0.55  0.00   0.326  0.67  likely_human  (signals disagree)
```

All five land where intuition says they should. The most informative row is
**borderline_formal_human**: the LLM and stylometrics both said ~0.95 "AI" for a real academic
sentence. Only the marker signal disagreed, which triggered the disagreement shrink and kept a

## Transparency label

The exact text readers see. Labels avoid numbers and jargon. The uncertain label says outright
that it is not an accusation, and the AI label always mentions the appeal path.

| Variant | When | Exact label text |
|---|---|---|
| **High-confidence AI** | `likely_ai` | "🤖 Likely AI-generated — Our automated checks found strong, consistent signs that this text was produced with an AI writing tool. This is an estimate, not proof, and the creator can appeal it." |
| **Uncertain** | `uncertain` | "❔ Origin unclear — Our automated checks couldn't tell with confidence whether a person or an AI tool wrote this. Treat this as \"we don't know,\" not as an accusation." |
| **High-confidence human** | `likely_human` | "✍️ Likely human-written — Our automated checks found no strong signs of AI generation in this text." |
| Under review *(status)* | after an appeal | "⏳ Under review — The creator has disputed the automated label on this work, and a person is reviewing it. No label is shown until the review is finished." |
| Verified human *(stretch)* | certificate issued | "✅ Verified human process — This creator shared earlier drafts showing how the piece developed, and Provenance Guard confirmed them." |

When showing the labels to someone who hasn't seen the project before, they were able to ascertain that it was "probably about detecting ai written text".

## Appeals workflow

- The creator sends `content_id`, `creator_reasoning` (10–2000 chars) and, optionally,
  `creator_id`. If `creator_id` is sent, it must match the original submitter; otherwise the
  request gets a 403.
- Unknown id → 404. An appeal that's already open → 409.
- On success: an `appeals` row is created, `submissions.status` → `under_review`, the public label
  becomes "Under review", and an `appeal_filed` audit entry stores the reasoning next to the
  original attribution and all signal scores. No automatic re-classification.
- `GET /appeals` is the reviewer queue. Each item has the original text, original attribution,
  every signal score with its details (including the LLM's reasoning), the creator's reasoning
  and timestamps.

## Rate limiting

| Endpoint | Limit (per IP) | Reasoning |
|---|---|---|
| `POST /submit` | **10 per minute; 100 per day** | A writer posting their own work submits a few pieces a day. 10/minute still lets someone upload a batch of short poems or move a back catalog in one sitting without hitting a wall. Anything faster than one submission every 6 seconds for a full minute is a script, not a person pasting work. 100/day is far above any real creator's output but caps how much a flooding script can push through. Every submission costs a Groq call, so this also bounds API cost and protects the free-tier quota for everyone else. |
| `POST /appeal` | **5 per hour** | Appeals are rare and deliberate. Each one lands in a human review queue, so spam here costs reviewer time, the most expensive resource in the system. 5/hour covers a creator contesting several pieces at once. |

Limits are keyed by IP because `creator_id` is unauthenticated and trivially spoofable. In
production I'd key on the authenticated account instead. Storage is `memory://`, which is fine
for a single dev process; production would use Redis so limits survive restarts and are shared
across workers.

## Stretch features

### Ensemble detection (3 signals)
Signal 3 (AI-phrase markers) joins the LLM and stylometrics. Weighting: 0.50 / 0.30 / 0.20.
Conflicts are resolved by (a) shrinking toward 0.5 when the scores spread by more than 0.5, and
(b) a voting rule: an AI verdict needs the LLM (≥ 0.6) **plus** at least one pure-Python signal
(≥ 0.5). Without that corroboration the score is capped at 0.74 ("uncertain"). Every `/submit`
response shows all three scores next to the ensemble result (see the sample response above).

### Provenance certificate
A creator can earn a **"✅ Verified human process"** badge by sending at least two earlier drafts
to `POST /verify` (oldest first) with their `content_id` and `creator_id`. The drafts must show
genuine revision:
- no step can be a near-copy (character similarity ≥ 0.97 is rejected);
- at least 40% of each draft's vocabulary must carry into the next draft;
- at least 60% of the last draft's vocabulary must appear in the published text.

On a pass, a certificate id (`PG-9FE23005D97E`) is issued, `status` becomes `verified_human`,
the public label switches to the ✅ text (visibly different from all three automated labels),
and a `certificate_issued` audit entry records the evidence. Failing requests get a `422`
response listing the reasons. Honest limitation: drafts can be fabricated. This raises the
cost of lying; it doesn't make it impossible.

```json
{"status": "verified_human", "verified": true,
 "certificate": {"certificate_id": "PG-9FE23005D97E", "content_id": "f2f54e71-3c39-45ec-af9e-93124322d97e",
                 "creator_id": "test-user-2", "issued_at": "2026-11-10T03:15:56.629Z"},
 "label": "✅ Verified human process — This creator shared earlier drafts showing how the piece developed, and Provenance Guard confirmed them.",
 "evidence": {"draft_count": 2, "step_char_similarities": [0.205, 0.791],
              "step_vocabulary_overlaps": [0.812, 0.974], "draft_lengths": [94, 218],
              "final_vocabulary_overlap": 0.974}}
```

### Multi-modal support (images via metadata)
The second content type is an **image, described by its structured metadata**: EXIF fields, PNG
text chunks, C2PA content credentials, width/height/format, and an optional short description
written by the creator. Provenance Guard doesn't analyze pixels. The upload step (or the
creator) sends the metadata as JSON, and it goes through the same pipeline as text:
validate → three signals → `combine()` → label → SQLite + audit log → appeal.

```bash
curl -X POST http://localhost:5001/submit -H "Content-Type: application/json" -d '{
  "content_type": "image", "creator_id": "demo-artist",
  "image": {"filename": "neon_city.png", "format": "PNG", "width": 1024, "height": 1024,
            "exif": {"software": "Midjourney v6"},
            "description": "A neon-lit city street at night in the rain."}}'
```

**Signals used for images** (code: `image_signals.py`, each 0 = camera/human-made, 1 = AI):

| Signal | Measures | Blind spot |
|---|---|---|
| **Generator fingerprint** (weight 0.45) | Generator names in software / C2PA fields (Midjourney, DALL·E, Stable Diffusion, Firefly…), diffusion parameters (`prompt`, `seed`, `sampler`, `steps`, AUTOMATIC1111's `parameters` chunk), C2PA digital source type `trainedAlgorithmicMedia` (0.97) or `compositeWith…` (0.85). With no fingerprint it scores 0.25, since metadata is easy to strip. A C2PA `digitalCapture` claim with no AI evidence scores 0.03. | Stripping or editing metadata removes it. The creator's description is deliberately not keyword-matched. |
| **Camera-capture evidence** (0.30) | Camera make, exposure settings (ISO, aperture, shutter, focal length), capture timestamp, GPS and lens, plus whether the dimensions look like a generator's (both multiples of 64, ≤ 2048 px). Score = 0.7 × (1 − capture evidence) + 0.3 × dimension score. | Social sites and screenshots strip EXIF, so a real photo can lose all of this. EXIF can also be forged. |
| **LLM judge** (0.25) | The same Groq model, with an image-specific prompt, reads the metadata JSON (and description). It's told that missing metadata is only weak evidence. | Sees only what the other two signals see, which is why it gets the smallest weight. |

**Conflict rules** reuse the text design: shrink toward 0.5 when the scores spread by more than
0.5, the same 0.75 / 0.35 thresholds, and the 0.74 cap. The corroboration rule is
image-specific: a "likely AI" verdict needs a generator fingerprint (≥ 0.6) **plus** the LLM or
capture signal (≥ 0.5). Missing camera metadata alone can never produce "likely AI".

**Image labels** (`labels.py` `IMAGE_LABELS`). They say "file information" because that is all
the system sees:
- 🤖 "Likely AI-generated image — This image's file information carries strong, consistent signs that it was made with an AI image generator. This is an estimate, not proof, and the creator can appeal it."
- ❔ "Origin unclear — We couldn't tell from this image's file information whether it was photographed, made by hand, or made with an AI tool. Many sites strip this information, so treat this as "we don't know," not as an accusation."
- 📷 "Likely camera or human-made — This image's file information shows signs of a real camera capture and no signs of an AI image generator."

## Known limitations

1. **Formal human writing, especially by non-native English speakers, is the system's weakest
   spot.** The reference economics sentence (written by a person) got **0.95 from the LLM and
   0.95 from stylometrics**: long words (5.9 chars on average), even sentence lengths (CV 0.26)
   and zero informal markers are exactly what both signals treat as AI. Only the marker signal
   (0.0) prevented a "likely AI" label. Formal human prose that happens to use "furthermore" or
   "moreover" would lose that protection and could be mislabeled. This is a property of the
   signals, not a data-size problem.
2. **Polished short descriptive writing scores AI-ish.** The two-sentence sunset paragraph from
   the assignment's curl example scored 0.625 ("uncertain"). Its two sentences are nearly the
   same length (CV 0.03, which maxes out the uniformity sub-score), and the LLM called its
   imagery "clichéd". A person writing a tidy, conventional paragraph looks like a model.
3. **Lightly edited AI evades the marker signal completely.** The remote-work text scored 0.0 on
   markers once the stock phrases were gone. The system can only call it "uncertain", never
   "likely AI".
4. **The LLM can be steered by the text itself.** For "This is a test submission for rate limit
   testing purposes only", the LLM reasoned that the text "explicitly identif[ies] itself as a
   test submission… a common human action". A text that claims to be human-written may nudge the
   strongest-weighted signal.
5. **Scores aren't calibrated against labeled data.** The thresholds come from reasoning plus a
   handful of probe texts, not a held-out evaluation set.
6. **Image attribution depends entirely on metadata.** Anyone can strip a Midjourney tag or
   paste fake camera EXIF onto a generated image. The system never looks at pixels, so a
   cleaned AI image lands in "uncertain" (or even "likely human", if forged camera EXIF is
   added). It also trusts that the submitted metadata really came from the file.

## Spec reflection

**How the spec helped:** writing the thresholds table (§2 of planning.md) *before* coding made
the scorer easy to check. The code's constants (`0.75`, `0.35`, the 0.6/0.5 corroboration rule)
could be compared line by line against the spec. The rule that "an AI verdict needs
corroboration" is what turned the formal-human false positive into "uncertain" instead of an
accusation.

**Where implementation diverged, and why:**
- **Uncorroborated scores are capped at 0.74.** The spec routed "≥ 0.75 without corroboration"
  to *uncertain*, but testing the LLM-outage path showed it returned
  `attribution: uncertain` with `confidence: 0.9`, where the number contradicted the label. I
  added a cap so the number and the label tell the same story.
- **Certificate similarity metric.** The spec used `difflib` character similarity for both
  "not copy-pasted" and "related". A genuine outline-to-full-draft revision scored 0.205 and was
  rejected. Character similarity drops when a draft roughly doubles in length, so "related" now
  uses vocabulary overlap (0.81 for the same drafts). The copy-paste check still uses character
  similarity.
- **Model and port.** The suggested Groq model is no longer served (404), so I switched to
  `qwen/qwen3.8-27b`. Port 5000 is taken by macOS AirPlay, so the app runs on 5001.
- **Multi-modal support was added after the spec.** planning.md §7 originally said "not
  planned". It was added later as images-via-metadata, with an addendum in planning.md §7.
  `combine()` gained a `content_type` parameter rather than a second scorer, so text and images
  share the same thresholds, disagreement shrink and cap. Only the weights and the
  corroboration rule differ.

## AI usage

1. **Spec → first signal and Flask skeleton (M3).** I gave Claude Code the assignment page
   and asked it to write planning.md first, then implement against it. It produced the Groq
   `llm_signal()` with the assignment's suggested model. Testing the function directly before
   wiring it in returned `404 model_not_found`, so I had it list the models available on my
   Groq account and switch to `qwen/qwen3.8-27b`, made configurable through `GROQ_MODEL`. I
   also kept the failure path: if Groq fails, the signal returns `None` and the AI label
   becomes unreachable, instead of crashing the endpoint.
2. **Scoring logic vs. the spec's thresholds (M4).** The AI-generated `combine()` implemented
   the spec, but probing the LLM-down case showed an "uncertain" result with confidence 0.9,
   which a reader would find contradictory. I overrode the spec's behavior with a 0.74 cap for
   uncorroborated scores and documented it as a divergence. I also checked that the label strings
   in `labels.py` match planning.md byte for byte (an automated check printed `True` for all
   three).
3. **Provenance certificate (stretch).** The first generated draft check used character
   similarity everywhere and rejected a realistic outline → full-draft revision (0.205). I had
   the "related" test replaced with vocabulary overlap and re-ran it: the same drafts pass
   (0.81 / 0.97), while unrelated junk drafts are still rejected with `422`.
