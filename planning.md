Provenance Guard is a backend service a creative-writing platform can call to estimate whether a
submitted piece of text was written by a person or generated by AI, communicate that estimate
honestly (including "we don't know"), and let creators contest the result.

Design principle that drives everything below: **a false positive (calling a human's work AI) is
worse than a false negative.** Every threshold, label and fallback leans toward "uncertain" or
"human" when the evidence is mixed.

---

## Architecture

```
                         SUBMISSION FLOW
 client ──(JSON: text, creator_id)──▶ POST /submit  [Flask-Limiter: 10/min, 100/day per IP]
                                          │ raw text
                ┌─────────────────────────┼──────────────────────────┐
                ▼                         ▼                          ▼
     Signal 1: LLM judge        Signal 2: Stylometrics      Signal 3: AI-phrase markers
     (Groq, JSON output)        (pure Python)               (pure Python)
                │ llm_score 0–1           │ stylometric_score 0–1    │ marker_score 0–1
                └─────────────────────────┼──────────────────────────┘
                                          ▼
                            Confidence scorer (weighted ensemble
                            + disagreement shrink + short-text guard)
                                          │ ai_likelihood 0–1, confidence 0.5–1, attribution
                                          ▼
                            Label generator (3 variants)
                                          │ label text
                                          ▼
                     SQLite: submissions row  +  audit_log row (event = "classified")
                                          │
 client ◀──(JSON: content_id, attribution, ai_likelihood, confidence, signals, label)──┘


                           APPEAL FLOW
 creator ──(JSON: content_id, creator_id, creator_reasoning)──▶ POST /appeal [5/hour per IP]
                                          │ content_id
                                          ▼
                     look up submission (404 if unknown, 409 if already under review)
                                          │ original decision
                                          ▼
                     submissions.status = "under_review"; appeals row created
                                          │ appeal + original decision
                                          ▼
                     audit_log row (event = "appeal_filed", reasoning + original scores)
                                          │
 creator ◀──(JSON: appeal_id, status "under_review", label "under review")──┘

 Reviewer view: GET /appeals (queue)   ·   Grader view: GET /log   ·   Stretch: GET /dashboard
```

**Narrative.** A submission enters `POST /submit`, passes the rate limiter, and its raw text is sent
to three independent signals (an LLM judgment, structural stylometrics, and a lexical "AI phrase"
detector). The scorer combines their 0–1 outputs into one AI-likelihood, maps it to one of three
attributions, and the label generator turns that into plain-language text; the decision is stored
and written to the audit log before the response is returned. An appeal enters `POST /appeal` with
a `content_id` and the creator's reasoning; the system flips the content's status to
`under_review`, stores the appeal, and writes an audit entry that carries both the appeal reasoning
and the original scores so a reviewer sees them side by side.

### API contract

| Method | Path | Accepts | Returns |
|---|---|---|---|
| POST | `/submit` | `{text, creator_id}` | `content_id, attribution, ai_likelihood, confidence, label, signals{...}, status` |
| POST | `/appeal` | `{content_id, creator_id, creator_reasoning}` | `appeal_id, content_id, status: "under_review", label, original_decision` |
| GET | `/content/<content_id>` | — | current status, label, scores |
| GET | `/appeals` | — | review queue: each appeal with the original text, scores and reasoning |
| GET | `/log?limit=N` | — | `{"entries": [...]}` most recent audit entries |
| POST | `/verify` (stretch) | `{content_id, creator_id, drafts: [...]}` | certificate or rejection reason |
| GET | `/stats`, `/dashboard` (stretch) | — | analytics JSON / HTML page |

## 1. Detection signals

Each signal returns a float **0 = reads human, 1 = reads AI**, plus a `details` object so the
response and the log can show *why*.

### Signal 1 — LLM judge (Groq)
- **Measures:** holistic semantic/stylistic coherence — does this read like the smooth,
  hedged, evenly balanced prose an LLM produces, or like a person with a specific voice,
  lived detail and imperfections?
- **Output:** the model is told to return JSON `{"ai_probability": 0.0–1.0, "reasoning": "..."}`;
  `llm_score = ai_probability` (clamped). Temperature 0 for repeatability.
- **Why it differs:** LLMs are good at recognizing the register they themselves produce
  (generic framing, "it is important to note", balanced both-sides structure, no concrete
  personal specifics).
- **Blind spots:** it is itself a model with no ground truth — it can be confidently wrong,
  is biased against formal/non-native writing that "sounds polished", and can be fooled by AI
  text prompted to "write casually with typos". Its scores also cluster at round numbers
  (0.1, 0.8, 0.9), so it is not well calibrated on its own.
- **Failure handling:** if Groq errors or times out, `llm_score = null`, the other weights are
  renormalized, and the result **cannot** be labeled "likely AI" (see thresholds).

### Signal 2 — Stylometric uniformity (pure Python)
Three measurable structural features, each mapped to 0–1, then averaged with weights:

| Feature | How it's computed | Mapping to AI-ness | Weight |
|---|---|---|---|
| Burstiness | coefficient of variation (std / mean) of sentence lengths in words | CV ≤ 0.20 → 1.0, CV ≥ 0.65 → 0.0, linear between | 0.40 |
| Word length | mean characters per word | ≤ 4.2 → 0.0, ≥ 5.4 → 1.0, linear between | 0.30 |
| Informality | rate of casual markers per word: lowercase sentence starts, standalone "i", `!`, `?`, `...`, ALL-CAPS words, slang (lol, gonna, honestly, kinda, ok, like…) | `1 − min(1, rate × 12)` | 0.30 |

- **Why it differs:** AI text is uniform — sentences of similar length, consistently formal
  vocabulary, almost no casual punctuation. Human writing is "bursty" and messy.
- **Blind spots:** cannot read meaning at all. Formal human writing (academic, legal,
  non-native speakers trained on formal English) looks "AI" on word length and informality.
  Poems with short repeated lines break the sentence-length math. Under ~40 words the
  statistics are noise.

### Signal 3 — AI-phrase markers (pure Python, stretch: ensemble)
- **Measures:** density of stock phrases that are heavily over-represented in LLM output
  ("it is important to note", "furthermore", "delve", "tapestry", "paradigm shift",
  "stakeholders", "in today's fast-paced world", "plays a crucial role", …; ~45 phrases).
- **Output:** `marker_score = 1 − exp(−0.35 × hits_per_100_words)` → 0 hits = 0.0,
  ~2 hits/100 words ≈ 0.5, ~6 hits/100 words ≈ 0.88.
- **Why it differs:** lexical, not structural or semantic — captures a third independent
  property: vocabulary habits learned from RLHF'd assistant output.
- **Blind spots:** trivially evaded by editing the phrases out; punishes human writers who
  naturally write "furthermore"; absence of markers is only weak evidence of human writing.

### Combining the signals
```
weights = {llm: 0.50, stylometric: 0.30, markers: 0.20}
if word_count < 40:   stylometric weight × 0.5, markers weight × 0.5   (statistics unreliable)
if llm_score is None: drop it and renormalize the remaining weights
ai_likelihood = Σ wᵢ·scoreᵢ / Σ wᵢ
spread = max(scores) − min(scores)
if spread > 0.5:  ai_likelihood = 0.5 + (ai_likelihood − 0.5) × 0.6   # signals disagree → pull toward uncertain
```
Conflict resolution (voting rule): the LLM gets the most weight because it is the only signal that
reads meaning, but it can never produce an "AI" verdict on its own — the AI verdict also requires at
least one of the two pure-Python signals to be ≥ 0.5 (see below).

## 2. Uncertainty representation

Two numbers are returned:
- `ai_likelihood` (0–1): the combined score above. 0.5 = "the evidence is balanced".
- `confidence` (0.5–1): `max(ai_likelihood, 1 − ai_likelihood)` — how strongly the evidence
  points to whichever side it points to. **A confidence of 0.6 means "the evidence leans one way,
  but only slightly; we would be wrong often if we acted on it"** — so 0.6 always maps to the
  uncertain label.

**Thresholds (asymmetric on purpose):**

| ai_likelihood | Extra condition | Attribution | Label variant |
|---|---|---|---|
| ≥ 0.75 | `llm_score ≥ 0.6` **and** (stylometric ≥ 0.5 **or** markers ≥ 0.5) | `likely_ai` | high-confidence AI |
| ≤ 0.35 | — | `likely_human` | high-confidence human |
| everything else (incl. ≥ 0.75 that fails the extra condition) | — | `uncertain` | uncertain |

The AI band (0.25 wide) is narrower than the human band (0.35 wide), and the AI verdict needs
corroboration — this encodes the false-positive asymmetry. A 0.51 and a 0.95 always produce
different labels.

**Validation plan:** run the four reference inputs from the assignment (clear AI, clear human,
formal human, lightly-edited AI) plus a short poem through `scripts/eval_inputs.py`, print each
signal separately, and check: clear AI → likely_ai, clear human → likely_human, both borderline
cases → uncertain. If any signal is the outlier, tune that signal, not the thresholds.

## 3. Transparency label design

Exact text (shown to readers next to the work):

| Variant | Label text |
|---|---|
| High-confidence AI | **"🤖 Likely AI-generated — Our automated checks found strong, consistent signs that this text was produced with an AI writing tool. This is an estimate, not proof, and the creator can appeal it."** |
| Uncertain | **"❔ Origin unclear — Our automated checks couldn't tell with confidence whether a person or an AI tool wrote this. Treat this as \"we don't know,\" not as an accusation."** |
| High-confidence human | **"✍️ Likely human-written — Our automated checks found no strong signs of AI generation in this text."** |
| (status) Under review | "⏳ Under review — The creator has disputed the automated label on this work, and a person is reviewing it. No label is shown until the review is finished." |
| (stretch) Verified human | "✅ Verified human process — This creator shared earlier drafts showing how the piece developed, and Provenance Guard confirmed them." |

Design choices: plain words ("estimate, not proof"), no numbers or jargon, the uncertain label
explicitly says it is not an accusation, and the AI label always tells readers an appeal exists.

## 4. Appeals workflow

- **Who:** the creator who submitted the content (`creator_id` must match the submission's
  `creator_id`; real auth is out of scope, so this is a basic ownership check).
- **Provides:** `content_id`, `creator_id`, `creator_reasoning` (required, 10–2000 chars).
- **System actions:** (1) 404 if the content doesn't exist, 403 if creator_id doesn't match,
  409 if an appeal is already open; (2) insert an `appeals` row (`appeal_id`, timestamps,
  reasoning, status `open`); (3) set `submissions.status = "under_review"` and swap the public
  label to the "Under review" text; (4) write an `appeal_filed` audit entry that copies the
  original attribution, all signal scores and the reasoning; (5) return a confirmation.
- **No automatic re-classification.**
- **Reviewer queue (`GET /appeals`):** each open appeal shows the original text, the original
  attribution, ai_likelihood, every signal score with its details (e.g. the LLM's reasoning
  string, the sentence-length CV), the creator's reasoning and when it was filed — everything
  needed to decide without re-running anything.

## 5. Anticipated edge cases

1. **Formal human writing / non-native English speakers.** An economics abstract or a cover
   letter by an ESL writer has long words, even sentence lengths and zero slang, so the
   stylometric signal scores it ~0.7–0.9 and the LLM may agree. Mitigation: AI verdict needs
   ≥ 0.75 *and* corroboration; marker signal is usually low for real academic prose, pulling the
   score into "uncertain". The appeal path exists exactly for this case.
2. **Short poems with repetition and simple vocabulary.** e.g. a 6-line poem repeating "I wait /
   I wait for you". Line-level sentence lengths are nearly identical (low CV → "AI-like") but
   word length is short ("human-like"); under 40 words the stylometric statistics are noise.
   Mitigation: halve the pure-Python weights under 40 words so the result leans on the LLM and
   lands in "uncertain" unless the LLM is very sure.
3. **Lightly edited AI output.** A person takes ChatGPT output, adds "I've been thinking…" and
   an em dash. Markers drop to ~0, stylometrics drop slightly; expected to land in "uncertain",
   which is the honest answer.
4. **Very short or empty input** (< 20 characters): rejected with 400 — there is nothing to
   measure.
5. **Groq outage / rate limit:** classify on the two local signals only; the AI label is
   unreachable without the LLM, so worst case is "uncertain".

## 6. Rate limits (planned)

- `POST /submit`: **10 per minute, 100 per day** per IP. A writer posting their own work submits
  a handful of pieces a day; 10/minute still allows a burst when someone uploads a back catalog
  of short poems, and 100/day caps a script's damage (and Groq cost) to a level a human would
  never hit.
- `POST /appeal`: **5 per hour** per IP. Appeals are rare and deliberate; this blocks spam
  that would flood the human review queue.

## 7. Stretch features (planned before building)

- **Ensemble detection (+1):** signal 3 above, weighting/vote rule in §1.
- **Analytics dashboard (+1):** `GET /stats` (JSON) and `GET /dashboard` (HTML) showing
  attribution mix (AI / uncertain / human counts and %), appeal rate (appeals ÷ submissions),
  average confidence, signal disagreement rate, and submissions in the last 24 h.
- **Provenance certificate (+1):** `POST /verify` with `content_id`, `creator_id` and at least two
  earlier drafts. Pass conditions: drafts are each different from the next (difflib similarity
  < 0.97 — not copy-pasted) but related (≥ 0.30), and the last draft is ≥ 0.60 similar to the
  submitted text. On pass, a certificate id is issued, status becomes `verified_human`, and the
  label switches to the "Verified human process" text (distinct ✅ badge). Logged as
  `certificate_issued`. Limitation: drafts can be fabricated; this raises the cost of lying,
  it doesn't make it impossible.
- Multi-modal: not planned.
